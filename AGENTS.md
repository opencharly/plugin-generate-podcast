# AGENTS.md — plugin-generate-podcast

The podcast desk: a topic plus a set of sources becomes a two-host discussion. Owns the skill
`generate-podcast` and the plugin candy `candy/plugin-generate-podcast`.

Canonical files:

- `candy/plugin-generate-podcast/charly.yml` — the candy: `description:`, the `plugin:` block, the ADE `plan:`.
- `candy/plugin-generate-podcast/schema/*.cue` — the **single source of truth** for every authored and wire
  shape; one package, four files (CUE permits one package per directory).
- `candy/plugin-generate-podcast/schema/testdata/{valid,invalid}.cue` — the two-arm fixture: the accept arm
  must validate, the reject arm must **fail**. A schema whose fixture cannot fail it is decoration.
- `candy/plugin-generate-podcast/params/cue_types_gen.go` — GENERATED by `cue exp gengotypes`; never hand-edit.
- `cmd/serve/main.go` — the external plugin entrypoint (`sdk.Main(NewProvider(), NewMeta(), CliMain)`).
- `.github/workflows/ci.yml` — gofmt/vet/test + the generated-params reproducibility job.

## Build / validate / test

```bash
charly -C . box validate          # candy + plugin: block + schema gate
cue vet ./candy/plugin-generate-podcast/schema   # the schemas themselves
go test ./...                     # from the candy dir (the Go module root)
```

The generated-params gate is `ci.yml`'s: regenerate with the pinned `cue@v0.16.1` and **fail if the
committed `params/cue_types_gen.go` differs**. The recipe (a plugin repo generates its own params; no
`charly task cue-gen` needed):

```bash
rm -rf /tmp/cg && mkdir -p /tmp/cg && printf 'package params\n' > /tmp/cg/schema.cue
for f in desk source episode manifest; do grep -v '^package ' candy/plugin-generate-podcast/schema/$f.cue >> /tmp/cg/schema.cue; done
cd /tmp/cg && cue exp gengotypes .
```

## A standalone project must declare what the umbrella supplies

Measured here, each by running the gate rather than reading a doc — the failure modes are silent:

- **`defaults: build:`** — every umbrella box omits it because the umbrella's `defaults:` supplies it. A box
  copied from an umbrella example then fails `charly box build` with
  `image <name>: build: field required (set in image, base, or defaults)`, **after `charly box validate`
  reported OK, 0 warnings** (validate never resolves the image).
- **`defaults: registry:` + `tag: auto`** — without them the deploy emits
  `Image=<registry>/<box>:<deploy>-<calver>`, a REMOTE ref, while the local build tags `localhost/<box>:<tag>`.
  The container then pulls a tag that was never pushed (`403 Forbidden`), exits 125, and systemd reaches
  `start-limit-hit`; the only symptom `charly start` prints is `command exited 1`.
- **`base:` takes a NAMESPACE-QUALIFIED box name** (`base: cachyos.cachyos` through the `cachyos:` import). A
  bare short name fails with `short-name "cachyos" did not resolve`, and a `@github…` ref with
  `invalid base image specification`; a fully-qualified registry ref also works.
- **A bed whose box is a build-time-only install needs `check-keepalive`**, composed **by ref**
  (`@github.com/opencharly/pod-check-keepalive:<calver>`) — a pod with no service of its own has nothing to
  stay up for, and `start` fails on the bare candy name.

## Landing

PR-only. The merge gate is the org-wide `charly/pr-validator` (required check `validate / validate`);
`tag-on-merge` writes `CHANGELOG/<CalVer>.md` from the PR body. The authoritative rulebook is the umbrella
`AGENTS.md` in `opencharly/opencharly`.

**Never declare a capability that is not implemented.** A `plugin.providers:` entry is a published claim —
it appears in the plugin's generated documentation page — so the provider and its leaves land in the same
change that declares them, or the declaration waits.
