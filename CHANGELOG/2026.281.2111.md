# 2026.281.2111 — ci: add the tag-on-merge caller so merges mint the CalVer tag + CHANGELOG

## Summary

This repo was created without the per-repo `.github/workflows/tag-on-merge.yml` caller, so its
first merge landed with **no CalVer tag and no `CHANGELOG/`**. This PR adds the missing caller
(byte-identical to the org pattern) and fixes the one repo setting that was still off the org
baseline.

Two changes, both repo-hygiene, neither touching the candy or the plugin:

1. **Added `.github/workflows/tag-on-merge.yml`** — the per-repo caller of the org reusable
   workflow `opencharly/.github/.github/workflows/tag-on-merge.yml@main`. This is the
   `repo-setup` checklist item 2 ("Add the per-repo `tag-on-merge.yml` caller — REQUIRED for
   CalVer tags and the CHANGELOG"); the org-required validator needs no per-repo file.
   The file is **adopted verbatim**: no adaptation is needed for a plugin repo, because the
   reusable workflow itself mints the subdir module tag `candy/<repo>/v0.<CalVer>` for
   `plugin-*` repos.
2. **Repo setting `delete_branch_on_merge`: `false` -> `true`.** `opencharly/.github/scripts/org-ruleset.sh`
   enforces exactly two settings that have no org-level default, `allow_auto_merge=true` and
   `delete_branch_on_merge=true`, and its `verify` mode fails on either being false. This repo
   was created outside that sweep, so the setting was still off; `allow_auto_merge` had already
   been repaired, this is the remaining one. Applied with the same API call the org script uses:

```
$ gh api --method PATCH repos/opencharly/plugin-generate-podcast -f delete_branch_on_merge=true --jq '{delete_branch_on_merge}'
{"delete_branch_on_merge":true}
exit=0

$ gh api repos/opencharly/plugin-generate-podcast --jq '{allow_auto_merge,allow_squash_merge,allow_merge_commit,allow_rebase_merge,delete_branch_on_merge,default_branch}'
{"allow_auto_merge":true,"allow_squash_merge":true,"allow_merge_commit":true,"allow_rebase_merge":true,"delete_branch_on_merge":true,"default_branch":"main"}
exit=0
```

`allow_squash_merge`, `allow_merge_commit`, `allow_rebase_merge` and `default_branch=main` are
unchanged, because they already match the org baseline (`opencharly/layer-charly` reports the
same four values).
